# Private first-time secret setup

Assessment date: 2026-10-03. Baseline: `d72eec64388bd4b5712a31fb1105378c895cc0da`. Delivery uses `master`, Python and Unreleased changes, with no release or version bump.

## Problem and chosen design

The previous helper printed every generated key and used an ordinary truncating write for `.env`. A preflight existence check did not prevent concurrent creation, symlink traversal or broad inherited permissions. Native CodeQL reported default console exposure and intended plaintext storage.

Keep Compose's existing `.env` contract and generate 32 random bytes with Python `secrets.token_urlsafe(32)`. Split templates, platform file creation, atomic publication and setup orchestration into small Python modules. Default output contains paths and instructions only. `--show-key` explicitly displays the newly generated key after successful publication; it never reads an existing secret. `--force` explicitly rotates only `.env`, preserving `config.toml`.

Create the staging file exclusively in the same directory, with POSIX mode `0600` or a protected Windows DACL allowing the current user SID full access, before writing secret bytes. Check Windows persistent ACL support before writing; fail closed on unsupported filesystems. Flush and fsync the complete file, then publish without replacement using an exclusive hard link or replace the directory entry atomically for explicit rotation. Reject symlinks, reparse points, nonregular files and multiply linked targets. Require an owned POSIX setup directory without group/other write access; on Windows the checkout and its ancestors must have trusted write/delete ACLs. A short exclusive setup-directory lock prevents simultaneous cooperating setup/rotation processes; interruptions can leave an empty lock that requires operator inspection.

Create missing nonsecret defaults atomically without replacement before publishing the key. Use POSIX `0644` for the defaults so the non-root container can read a bind-mounted config; Windows defaults inherit the trusted checkout ACL. Never overwrite an existing config, including during rotation. Setup can leave newly created nonsecret defaults when later secret publication fails; it must preserve the old key and clean its own staging files on handled failures. Atomic visibility is distinct from crash/power-loss durability, and separate files are not a transaction. Secret staging names use `.env.setup-*.tmp`, covered by the existing `.env.*` Git ignore rule. Crashes can leave private staging or an empty lock; inspect only after confirming no setup is active.

## Alternatives and tradeoffs

| Option | Pros | Cons | Decision |
|---|---|---|---|
| Restrict an ordinary file after writing | Small change | Secret exposure window; truncation and link races | Reject |
| Exclusive final-file write | Prevents overwrite | Readers can observe partial content; failed writes leave incomplete secrets | Reject |
| Private same-directory staging and atomic publication | Existing Compose compatibility; private bytes from creation; complete visible content | Filesystem/ACL support and trusted directory required | Implement |
| Secret manager or Compose file-mounted secrets | Central rotation and deployment separation | Runtime/environment contract migration and operational dependencies | Separate deployment design if needed |

## Security scope and official research

Research was discovered through web/GitHub MCP on October 3, 2026. The Python [secrets documentation](https://docs.python.org/3.12/library/secrets.html) supports cryptographic token generation with explicit entropy. Python's [OS APIs](https://docs.python.org/3.13/library/os.html) document exclusive creation, hard links and atomic same-filesystem replacement; Windows chmod is not a discretionary ACL. Microsoft [file security](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights) documents creation-time descriptors, inherited defaults and preservation when renamed. [CreateFile](https://learn.microsoft.com/en-us/windows/win32/api/FileAPI/nf-fileapi-createfilea) documents the security attributes and exclusive creation contract used through the Unicode entrypoint. [Volume information](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumeinformationbyhandlew) identifies persistent ACL support, while [SDDL](https://learn.microsoft.com/en-gb/windows/win32/secauthz/security-descriptor-string-format) defines protected DACLs. [Token information](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-gettokeninformation) supplies the current user SID; [descriptor conversion](https://learn.microsoft.com/en-us/windows/win32/api/sddl/nf-sddl-convertstringsecuritydescriptortosecuritydescriptorw) and [SID conversion](https://learn.microsoft.com/en-us/windows/win32/api/sddl/nf-sddl-convertsidtostringsidw) define buffer ownership and cleanup.

Plaintext is necessary for the current Compose/environment integration and protected as a recoverable service credential, rather than a password hash. `--show-key` is deliberate local disclosure and can expose a key to terminal history/capture/redirection; prefer a private editor. File access controls do not protect against administrators, backup privilege, the current user, compromised Docker/host accounts or an attacker who controls checkout directory entries. Existing `.env` files are never silently read, chmodded or repaired; rotate explicitly and synchronize Classifarr. No scanner suppression is added just to obtain zero alerts.

## Validation and outcome

The implementation uses `secret_setup.py`, `secret_publication.py`, `secret_windows.py` and `setup_templates.py`, keeping the CLI small. The existing defaults and public service API schemas are unchanged. Bash and PowerShell launcher fixtures generate once, preserve the key on restart and show private-editor instructions without printing its value.

Full locked Linux QA passes **758 tests**, with seven skips: two optional production tests and five native Windows cases. The new suite contains **48 cases**: Linux runs 43; native Windows/Python 3.14 runs 32 and skips 16 POSIX/unavailable-symlink cases, complementing Linux coverage. Tests exercise exclusive concurrent writers, a competing setup process, explicit display/rotation, partial-publication and I/O failures, linked targets, staging-name collisions, strict/permissive umasks and config preservation. Windows inspects protected single-user DACLs on the empty file before the first write and on the published/rotated file, rejects a junction root, and injects unsupported-volume/query/CRT failures before any data. This does not claim a real FAT-volume trial or another Windows user's impersonated access check.

A separate native Linux process drops to UID 1002 and confirms `.env` access is denied while `config.toml` is readable. Actual QA pip check and exact inventory verification pass for 67 unchanged wheels after PR 34's input renewal. Application coverage remains **94.31% lines / 88.71% branches**, above unchanged floors. Ruff, scoped Pyright, copyright, source/whitespace and secret checks are recorded in the [validation archive](validation/secret-setup-2026-10-03.json).

CodeQL 2.27.1 security-extended analysis completes and reports **two context-specific alerts**: key output under the explicit `--show-key` branch and world-readable nonsecret config defaults. Default key output is removed; the public config is required for the non-root bind mount. The former plaintext-storage alert is absent from this modular analysis, but the key remains intentionally plaintext in the private file. These results are not proof of absent vulnerabilities. Neither alert is suppressed, and the archive retains rules and locations.

Final recommendation: retain Python, private atomic local setup and explicit display/rotation, plus complete dependency/model/CI contracts. Next bound total HTTP upload and DNS/download lifetime; then calibrate target accelerators/concurrent inputs and add recurring native Windows setup validation. Trusted directory ownership, supervisor/process crash cleanup and deployments needing managed secret rotation remain explicit operational boundaries.

A final full-history scan also identified two public log digests in the previous CI record. The separate [digest classification design/outcome](secret-scan-digests.md) documents their verification, exact rule/path/value exceptions and seven native negative controls. Default secret rules remain active; published history is preserved.
