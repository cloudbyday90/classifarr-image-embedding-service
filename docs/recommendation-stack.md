## Final recommendation stack

Keep Python/FastAPI/AnyIO and scoped ingress, admission, queue, execution and batch services. Maintain small routes/modules with explicit ownership. Use pure ASGI `ingress_middleware`, Starlette's supported body middleware and `input_limits`/`image_input` for resource policy. Keep URL policy and transport in `remote_url`/`remote_fetch`. Native tensor libraries perform expensive inference; any later language experiment requires measured benefit and matching model/API/backend contracts. All future JavaScript should use ES Modules; locally adopted checkout and setup-python actions are ESM.

Use CPU-only Torch for the default image, cu130 Torch/NVIDIA CUDA 13 for modern NVIDIA GPUs, the documented cu126 profile for older amd64 NVIDIA hardware, and matching OpenVINO bindings/base for Intel deployments. Keep exact native-backend profiles separate from shared requirements and resolve Torch from a single official index before constrained PyPI installation. Keep non-root runtime execution and writable caches scoped to the application.

Validate with event-controlled worker tests, actual tiny native-model checks, network-disabled service smokes, and strict installed-package audits. Publish only from release tags after unit/backend gates. Immutable base/action image references require reviewed updates; default Docker bases receive weekly Dependabot proposals, while the legacy base override and direct scanner image require explicit digest review.

Keep the selected 16 MiB HTTP, 10 MiB compressed-image, 32 MiB batch-byte, 16-million source/resize-pixel, and 32-million aggregate-pixel defaults. Admit at most eight complete ordinary HTTP lifetimes per worker; reject immediately with 503 and no body receive. Preserve read-only probe access and native inference ownership after HTTP timeouts. Launch explicitly with one worker, server concurrency 64 and backlog 128; use tunable 4 GiB/no-swap Compose containment. Measure pinned production model/cache/tensor/input peaks before changing these settings. Apply inline checks before inference admission and remote/direct-call checks in the worker; preserve Pillow's policy and deterministic image closure.

Use only approved public numeric addresses for remote connections, verified original-host TLS identity, at most three validated redirects and four interleaved approved-address attempts before connection success. Refuse ambiguous authorities, credentials, mixed/empty unsafe DNS and HTTPS downgrades. Bound final decoded bodies and close responses/pools; avoid ambient proxy/netrc/CA overrides. Preserve authentication, default-disabled access, 400 policy/413 limit/500 download statuses and sanitized ordered batch failures. Follow with production-model/cache contracts and total-lifetime controls.

## Delivery outcome

The current aggregate-ingress iteration preserves the previous execution/admission/input/remote/backend work. The complete suite passed **456 tests** on Python 3.12 with pytest-cov 7.1.0; focused validation passed **123 tests**. Coverage is **93.84% lines and 87.93% branches**, above the unchanged 89.42%/79.37% floor. Strict OSV audits checked the actual CPU runtime's **56 packages** and QA environment's **67 packages** with zero known vulnerabilities and zero skips; no advisory suppression was used.

The newly rebuilt CPU image passed its shipped-script smoke with a real native CLIP projection, non-root/cache checks, authentication, configured-port launcher/healthcheck and shutdown. The offline live server rejected excess requests while an incomplete upload owned capacity, kept health/ready available, recovered after disconnect and preserved admitted 401/413/422. Actual cgroup v1 memory/swap files and all three Compose renderings confirmed 4 GiB memory with no additional swap.

In the controlled approximately 1 MiB-upload experiment, 80 clients retained **163.28 MiB** of traced Python allocations with only the old boundaries, versus **16.44 MiB** with ingress capacity eight. Exactly eight bodies were received; 72 requests were rejected before receive. This experiment holds a fake inference worker and measures Python retention, not production RSS/VRAM or throughput. Owners returned to zero after release.

Ruff, scoped Pyright for changed services, workflow lint, compilation, copyright, coverage ratchet and whitespace checks passed. Randomly selected PR 51 is applied through the verified immutable 2.6.0 reusable workflow commit. Its exact upstream completion guard passed eight local cases; actual native scanner/reporter controls passed clean and unchanged-vulnerability comparisons and failed newly introduced vulnerabilities. GitHub MCP reconfirmed the original PR remains open/unmerged. Hosted GitHub/SARIF behavior remains untested locally, and the upstream nested scanner image uses a mutable tag.

The prior [backend iteration](backend-build-recommendation.md) separately records five-image smokes/audits and the RTX 5070 Ti check; those profiles were not all rebuilt here. The earlier [remote record](remote-image-destinations.md) retains its reproduction, TLS/connection and independent review evidence; input/PR/language records retain their historical results. CUDA ARM's unsupported vendor SBSA metadata stays deferred with pip check strict. No production-weight capacity measurement or comparative Rust benchmark is claimed.

Delivery is directly to local/remote `master`, per user instruction, without a separate branch. No release, tag, version bump or upstream PR merge is created. These checks improve specific destination/resource properties and package hygiene; they are not a full repository security audit.
